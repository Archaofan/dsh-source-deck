# SourceDeck 阶段 2（V3a 无模型链路）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在沙箱 `0.2.1-rc.2` 内完成“手动添加资料 → 对话/面板筛选 → 提交给 Agent”的无模型链路。

**Architecture:** 单包双半。Host 半用 Cordis 函数插件注册 `source_deck` 域、`deck_submit_sources` 工具、log-only 会话事件，并以 `TypertRemoteService` 暴露一个命名空间 `sourceDeck`；Client 半经 `ctx.remote.$mount` 挂载自带的 Remote 描述，渲染右栏面板、对话流候选卡片与 `input.right` 入口。为降低树外插件的生成器依赖，V3a 的 wire 面先用**单个 `request(op, bodyJson)` 方法**（JSON 载荷），Host 内部分派到具名操作；后续可用 typert 生成器替换为具名方法而不改 UI。

**Tech Stack:** TypeScript、Cordis、tsdown、zod、`@deepseek-ai/dsh-typert-protocol`、`ctx.storageDomain`（per-record JSON）、React（Client slot 组件）。

**Spec:** `docs/design/2026-10-17-solution-design.md`（方案 A，§4–§9）；基线证据 `docs/research/2026-10-17-0.2.1-rc.2-interface-delta.md`。

## Global Constraints

- 基线 `@deepseek-ai/dsh@0.2.1-rc.2`、`@deepseek-ai/cordis@4.0.5`；不引入 alpha 接口。
- 产品版本从 `0.1.2` 起每次安装前 bump。
- `source_deck` 域名/表名匹配 `^[a-z][a-z0-9_]*$`；记录只增不改。
- 日志事件必须 `ignorable: true`，data 为无损 JSON。
- Client bundle 继续 lazy-CJS；外部请求仅基线 `PLATFORM_MODULES` + 明确内联白名单。
- 所有验证在沙箱 Desktop 内进行；不碰日用 DSH。

## Review Focus

- 树外插件能否在 Host 解析 `@deepseek-ai/dsh-typert-protocol`（若不能，Remote 方案需改为官方 commands 桥，属设计变更）。
- 单 wire 方法的 JSON 往返是否被 gateway 的 SRC 校验接受（参数名、返回 codec）。
- 域记录写入与事件 emit 的先后/失败边界。
- 同一会话重复提交的幂等（requestId）。
- 面板与卡片对同一 verdict 的双向一致。
