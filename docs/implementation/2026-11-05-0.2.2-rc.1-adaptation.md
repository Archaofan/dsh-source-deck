# 0.4.1：适配 DSH 0.2.2-rc.1

> 中文（默认）

用户于 2026-11-05 告知沙箱已升级新版 DSH，要求资料台（SourceDeck）做适配。生产 Desktop 与共用沙箱均为 `0.2.2-rc.1`（生产升级记录在工作区 `operations/production-upgrade-20261105/`）。本轮只做基线适配，不新增功能、不改数据表、不操作生产；是否发布 0.4.1 Release 未获指示，本文按“开发版已适配、尚未发布”记录。

接口变化与逐项证据见[0.2.2-rc.1 接口差异](../research/2026-11-05-0.2.2-rc.1-interface-delta.md)。

## 实际变化

- `package.json`：版本 `0.4.0 → 0.4.1`；四个 DSH peer 精确 `0.2.2-rc.1`，Cordis 精确 `4.1.0`；所有官方 Client 类型包与 devDependencies 同步 `0.2.2-rc.1`。
- 新增 peer + devDependency `@deepseek-ai/dsh-tool-executor-native@0.2.2-rc.1` 与 `@deepseek-ai/dsh-tools@0.2.2-rc.1`。0.2.2 把工具呈现/执行从 `tools.presentAs()` 移到每个 scope 的 executor 插件；研究 worker 必须在自己的 scope 选择 native。
- `src/research-runtime.ts`：删除已不存在的 `tools.presentAs('native')`；改为动态 import 官方 native executor，并 `agent.ctx.plugin(executor)` 挂到 worker scope，保留原有 `restrict`/`guard`。新增 `mountNative` 测试接缝，避免单元测试加载宿主工具树。
- `tsdown.config.ts`：把 executor 加入 Node 外部依赖，避免把宿主执行器打进插件包。
- `pnpm-workspace.yaml`：`minimumReleaseAgeExclude` 更新到 `0.2.2-rc.1`、Cordis `4.1.0`、cosmokit `1.9.0`。
- `tests/research-coordinator.test.ts`：两个运行时回归改为注入 `mountNative` 探针，断言只有研究 worker 会触发挂载；不再 mock 已删除的 `presentAs`。
- 没有 UI、CSS、八表 schema、研究提示、Remote 协议或引用格式变化。

安装只用官方脚本：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ..\sandbox\dsh-desktop\scripts\Install-Plugin.ps1 -Project dsh-source-deck -PackagePath .\dsh-source-deck-0.4.1.tgz
```

- 退出码 0；profile `dependencies` 为 `dsh-source-deck 0.4.1`，`dsh.profile.bundles` 保留本插件；安装后未出现 0.4.0 那样的兼容拒绝，也没有授予版本豁免。
- 启动 `Start-Desktop.ps1 -Project dsh-source-deck`，Host `http://127.0.0.1:3797` 返回 200；实际页面为深色中文、`0.2.2-rc.1-66491b0`。
- 通过 Electron renderer 的 CDP 实际操作并回读 DOM（只读探针在项目专属 `test-workspaces/dsh-source-deck/`，不进 Git）：
