## 2. 与插件系统相关的 release notes 变更（影响面）

0.2.1 系列新增/变更中与第三方插件（尤其 SourceDeck）相关的条目（rc.1 与 rc.2 一致）：

- 自定义插件索引源；插件启用/停用/卸载/更新后的依赖同步；启用热重载（更新或重装的可替换插件直接生效）。
- 实验性 Session 状态记录接口（插件写入/读取自己的会话记录）。
- pi-ai 路由按模型能力处理系统提示词更新与工具动态增删。
- 第三方插件兼容性**优先按 `engines.dsh` 判断**；未声明时沿用原 peer 规则。
- 移除运行时 invariant 插件与各包 `./invariant` 导出（SourceDeck 不发布 invariant，无影响）。
- 子路径插件不再读取独立 `package.json`（SourceDeck 是普通带 `dsh.bundle.patch` 的包，不是子路径插件）。
- 输入区统计扩展拆为 `activity` 与 `usage`（SourceDeck 使用 `conversation.input.right`，不受影响）。
- 已发送消息中的密钥/令牌默认脱敏（与既有凭据纪律方向一致）。
- 桌面端默认使用系统分配端口（沙箱仍用官方 `webserver` `port: 0` 覆盖，行为一致）。

## 3. 对已批准方案的含义

1. **方案 A 的挂点全部仍在**：右栏 tab、对话流业务节点、输入区入口、设置页、toolview、自建 Remote、`session.prompt`、域存储、log-only 事件均可继续使用，阶段 2 无需改设计。
2. **产品 peer 仍是 `0.2.0-rc.2`**：在 0.2.1-rc.2 下会被兼容门拒绝。适配验证使用**仅沙箱**的 `0.1.3-adapt.1` 包（peer 改 `0.2.1-rc.2`、cordis 改 `4.0.5`，devDependencies 同步到 `0.2.1-rc.2` 类型包），产品 `package.json` 未改。
3. **是否切换支持基线是用户决策**（见 HANDOFF）。若切换，建议同时评估 `engines.dsh`（可表达跨 RC 范围）而不是继续精确 peer；若保留精确 peer，则只能支持单版本。
4. **PLATFORM_MODULES 新增 `zod` / `@tanstack/react-virtual`**：SourceDeck 目前不 import 二者；阶段 2 若引入，应把它们加入本地 `CLIENT_EXTERNALS` 以复用 shell 模块身份，而不是内联副本。
5. **新预设允许更宽的 `INLINE_SAFE` 白名单**：SourceDeck 本地复刻的纯度门更严格（只允许基线行）。阶段 2 如需内联 `dsh-*` 纯类型/协议层值，需按新预设名单逐项放行并在文档记录。
6. **构建环境**：0.2.1 的 client build 会执行 `git rev-parse HEAD`。本机**有** git（Hermes 自带 `git 2.54.0`，`C:\Users\Administrator\AppData\Local\hermes\git\cmd\git.exe`），但沙箱进程 PATH 默认不含它；rc.2 的源码获取已直接使用该 git（shallow fetch + clean status）。构建仍通过官方支持的 `DSH_CLIENT_COMMIT_HASH` 显式值提供基线 commit（构建记录实测 `687f282`），以避免沙箱 PATH 与 worktree 状态影响产物。
