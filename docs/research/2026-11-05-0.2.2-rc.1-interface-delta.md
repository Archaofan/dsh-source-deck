## 唯一需要改代码的接口：工具呈现

0.2.1 的 `ctx.tools.presentAs('native')` 在 0.2.2 不存在。官方升级指南把工具模式改成显式 executor 插件：

- `@deepseek-ai/dsh-tools` 只保留注册、限制、守卫和执行管线；`mode` / `maxParallelSubCalls` 配置字段被拒绝。
- `@deepseek-ai/dsh-tool-executor-native` 或 `@deepseek-ai/dsh-tool-executor-ptc` 之一在部署、preset 或 Agent scope 中挂载；nearest scope 生效，同一 scope 不允许两个 executor。
- 子智能体未显式选择 preset 时加入父级当前 preset 的 composition，因此父级用 PTC 时研究 worker 也会继承 PTC；SourceDeck 必须像旧版强制 native 一样，在 worker 自己的 scope 挂 native executor。

0.4.1 的实现：研究 worker 的 `agent/created` 回调在 `restrict`/`guard` 之后动态 import 官方 executor 并以 `agent.ctx.plugin(executor)` 挂到 worker scope。worker scope 比 preset scope 更近，因此覆盖继承的 PTC 选择；限制与守卫仍把可见工具收窄为 `web_search`、`web_fetch`、`deck_submit_sources`。测试通过注入 `mountNative` 探针避免加载宿主工具树；真实装载在固定 RC Host 中由“子智能体已创建、研究轮次进入执行后因未配置模型而报错”验证，监听器未抛错。

## 不影响 SourceDeck 的其他变化

- 对话/输入契约新增引用 chip 的 quotes、`insertQuote`、附件上传字段与 `sending` 阶段；SourceDeck 只用 `ReferenceInsert`/`TokenSpan` 与插入事件。
- Chat 视图注入新增 `fileDrag`、`resolveFilePath`、`dispatchInteraction`；SourceDeck 的卡片只消费 Node 数据与 `openDeck`/`decide`。
- Session 增加 `TOOL_ACTIVATION_FAILED` 结束原因、subagent 归因文档和 v4 迁移；SourceDeck 的记录仍是 ignorable 的 `plugin:` 记录。
- Typert 资源声明新增 `resolve` 提取器；SourceDeck 的手写 remote-info 不使用资源声明。
- `sessionProjections.register` 变 async；SourceDeck 未使用该服务。
- 插件 bundle manifest 新增 `platforms`、`listedByDefault`、`optionalDependencies`；SourceDeck 均不声明。
